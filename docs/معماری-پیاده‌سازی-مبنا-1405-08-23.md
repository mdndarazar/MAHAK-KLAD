## ۲. فاز ۱ — آینه فقط-خواندنی (CloudSyncService)

**هدف:** عدد آبی = کشو+کارتخوان (`totalTheoreticalDifference` از `CustodyDiscrepancyCase`) + فروش/برگشت/چک دقیقا مثل دسکتاپ به ابر برود، بدون محاسبه مجدد.

- **منبع داده:** `AuditLog` فقط محرک است (۱۵۶+ نقطه ولی `audit()` خطا را می‌بلعد و `CREDIT_BULK_GENERATE` یک ردیف برای کل دسته است) — مقدار عدد آبی **مستقیم از `CustodyDiscrepancyCase.totalTheoreticalDifference`/`CashSession`** با `SELECT` خوانده شود (ستون ذخیره BigInt → رشته). Heartbeat hash روی هر دو `lastAuditId`+`lastCaseId`. برای شیفت باز الان هیچ `Case`ای نیست — پیش‌نمایش از `cashboxService.expected()` (۲ث timeout، برچسب «پیش‌نمایش: آخرین مرز ساعت X») + عدد نهایی از `Case`.
- **Reader امن بدون query_only:** از همان `prisma` سراسری استفاده کن (نه کلاینت دوم — کلاینت دوم دستگیره دائمی روی shop.db نگه می‌دارد و `copyFile` ریستور ویندوز را می‌شکند `BackupService:611`). `cloudReader.ts` فقط `ro(sql,params)` export کند که فقط `^SELECT\b` بپذیرد و هر `; ATTACH PRAGMA INSERT|UPDATE…` را رد کند + تست CI روی `cloud/` که هیچ `.create/.update/.delete/$executeRaw` نداشته باشد. هر خواندن `Promise.race` ۲ث timeout؛ `SQLITE_BUSY` → رد چرخه + `failStreak++`. خواندن‌ها صفحه‌ای ≤۲۰۰ ردیف + `await setImmediate` بین صفحه تا commit فروش معطل نشود (WAL خاموش است — هرگز روشن نکن).
- **سه کانال:** 1) Heartbeat snapshot ≤۴KB هر ۳۰ث (اگر hash نخورده نفرست)، 2) event سبک (≤۵۰۰ بایت)، 3) pull-on-demand (ابر `report.fetch` می‌فرستد، فروشگاه وقتی بیکاره می‌خواند — ۱ بار در ۱۰ث، ≤۲۰۰۰ ردیف). فقط allowlist فیلد — هیچ `panelAuth`/`vault.key`/PIN به ابر نرود.
- **کلید یکتا:** `(storeId, dbEpoch, auditId)` — `dbEpoch` UUID تصادفی در `userData/cloud-state.json` کنار `panel-vault.key` (نه در DB چون DB ریستور می‌شود). تشخیص ریستور با ۳ سیگنال: `max(auditId) < lastAcked`، هش ردیف `lastAuditId` نخواند، `fs.watch` روی `last-restore.txt` (BackupService:617). با تشخیص → epoch جدید + Snapshot کامل + `epoch.changed` به ابر + `revokeAll()`.
- **آفلاین & Worker:** Main فقط SELECT می‌کند و به Worker `postMessage` می‌دهد؛ Worker فقط CPU/شبکه (JSON/gzip/HMAC/WS/JSONL/backoff) — DB نمی‌خواند (Prisma در Worker موتور جدا می‌خواهد). `new Worker(?nodeWorker, {maxOldGen 128MB})` — اگر پرید ۳ بار backoff بعد ۵دقیقه توقف. JSONL حلقه‌ای ۵۰MB در `userData/cloud-spool/` + `outboxPending/outboxOldestSec` در Heartbeat. بعد از وصل به ترتیب و idempotent.
- **WS خروجی:** سرور هرگز به Electron وصل نشود (NAT) — Electron خودش `wss://.../live` را باز نگه دارد (HMAC `seq||body` + seq ضد Replay + Ping ۳۰ث). جفت‌سازی با کد QR و `safeStorage.encryptString` (fallback mode 0o600). Kill-switch محلی با `assertManagerPassword`. polling fallback اگر WS قطع شد.

## ۳. فاز ۲ — قفل هوشمند (RemoteGrantRegistry + ≤۱۰ خط AuthService `gt-`)

**جریان کاربر:** فروشنده دکمه «درخواست مجوز» کنار قفل → کد ۶ رقمی (شناسه جفت‌ساز، نه راز) روی دسکتاپ → مدیر در PWA کد را چشمی تطبیق + PIN دوم → ابر فرمان امضاشده (HMAC/Ed25519 + `requestId`+`nonce`+`TTL 60s`) → Electron چک امضا → `RemoteGrantRegistry.create({panel, ownerWindowId, tier, exp, memberId})` → به Renderer بنر «مجوز دریافت شد — ۱۰ دقیقه» (حساس ۵ دقیقه) — اگر ۳ دقیقه استفاده نشد خودکار بسته.

**پیاده‌سازی:**
- `RemoteGrantRegistry.ts`: Map `{id, panel, ownerWindowId, tier, approvedAt, claimBy(+3min), expiresAt, memberId}` + تایمر **مطلق مونوتونیک** `performance.now()` (نه `isPanelUnlocked` که `alive(true)` با touch تمدید می‌کند) → در انقضا `clearPanelScope` + `REMOTE_GRANT_CLOSED`. سقف tier محلی `creditBulkIssue/cardTransfers/creditVoid`=۵دقیقه (ابر نمی‌تواند بلندتر بدهد). `revokeBy`/`revokeAll` برای Panic/حذف. گره به `webContents.id` — `destroyed` پاک کن. مهلت claim ۳دقیقه (تاییدشده منتظر claim، از claim ۱۰/۵ دقیقه شروع).
- **≤۱۰ خط AuthService (تنها استثنا — کلاد۹):** ۳ خط هسته **داخل `verifyPanel:~1043 بعد normalizePanelKey داخل withGateAttempt` (بین ۷۸۹-۷۹۰ برای Strict و ۷۴۷-۷۴۸ برای غیرStrict)** — `if (pass.startsWith('gt-')) return registry.consumeOneShot(owner,panel,pass.slice(3))` → `PANEL` یا throw fail-closed — همه ۲۰ Strict + غیرStrict + `ipc:1522` + `panelSession:241` پوشش داده می‌شود (کلاد۸: ۲۰ Strict واقعی نه ۱۳/۲۹، `CardTransfer:324` کامنت). قبل از `readPanelLocks` وگرنه `OPEN` کوتاه می‌کند. دو توکن `gt-U` (پنجره ۱۰/۵د) + `gt-A` (one-shot هر Strict) — چون Strict هر بار رمز می‌خواهد (کلاد۸). ۱ خط import + کامنت + قفل ۵ خطا per(پنجره،پنل) جدا از `AuthLockout`. `assertManagerPassword:581` و `authService.verify:846` عمدا بدون `gt-` (فقط مدیر). برای «۳ دقیقه بی‌استفاده» بدون `peekPanelExpiry` عملا ۵ دقیقه. کلاد۴: برای نشت بین ۵ پنجره نیاز به ۳ خط `currentPanelOwner()` در `panelSession.ts`.
- **IPC جدید (فایل جدا):** `remoteAuth:request/status/cancel/banner/claim` — فقط افزودنی، `ipc/index.ts` دست نخورد (`ipcMain.handle` مستقیم + `event.sender.id` → `explicitOwner`). `ManagerGate.tsx` ≤۱۵ خط + `RemoteRequestBox`، `useManagerSession.tsx` ≤۴ خط (poll هر ثانیه). **۱۹ دیالوگ خانواده دوم:** `PasswordField.tsx` ≤۸ خط — وقتی Registry مجوز فعال دارد خودش `gt_ok` را با `onChange` پر می‌کند و «🔓 مجوز مدیر فعال» نشان می‌دهد (بدون لمس ۱۹ فایل خط قرمز) + preload ۲ خط برای `remoteAuth:*` (F1) + جفت‌سازی بدون فایل رندرر: منوی «اتصال موبایل» با `setImmediate` بعد `installApplicationMenu()` + dialog بومی (نیاز به تایید ۲ خط Route اگر بخواهی صفحه بسازی).
- **امنیت:** CSPRNG + `codeHash`, `requestId`+`nonce`+TTL60s, `normalizePanelKey` چک، آفلاین=رمز مستقیم، ۲ مدیر اولین `UPDATE ... WHERE PENDING RETURNING` برنده.

## ۴. فاز ۳ — چند مدیره (ابر + کاتالوگ خودکار)

**نقش‌ها:** ۱ OWNER + تا ۴ MANAGER/VIEWER = سقف ۵ فعال (شامل دعوت‌های معلق ۴۸ساعته خودکار آزاد). جدول `members` در **ابر** (نه `User` محلی) + `one_active_cap` + `CHECK seat_no 1..5` + `UNIQUE(store_id,seat_no)` + `advisory_lock`. VIEWER فقط دیدن، MANAGER فقط پنل‌های تیک‌خورده، OWNER همه + Panic + دعوت/حذف.

- **دعوت بدون پیامک:** OWNER «افزودن مدیر» → نقش + تیک پنل → کد دعوت ۱۰-۱۲ کاراکتری یک‌بارمصرف ۴۸ساعته (hash در DB) → لینک/QR از واتساپ/بله/حضوری → مهمان یوزر+رمز (≥۱۰ نویسه، لیست رایج رد) + PIN دوم → `PENDING_OWNER_APPROVAL` تا OWNER تایید کند (`UPDATE ... RETURNING`). حذف → `DISABLED` + ابطال همه refresh/WS/devices + `revokeBy`. بازیابی: MANAGER از OWNER (دعوت تازه)، OWNER از ۱۰ کد بازیابی یک‌بار چاپ + مسیر دسکتاپ QR با `assertManagerPassword`.
- **کاتالوگ خودکار:** `CloudSyncService` در hello/heartbeat `LOCKED_PANELS` را همان‌طور که هست (`key,title,hint`) + `catalogHash` می‌فرستد → `panel_catalog` در ابر. پنل جدید خودکار ظاهر می‌شود، پیش‌فرض فقط OWNER (fail-closed). `member_panel_acl(member_id, panel_key, allowed)` + `can_money` برای حساس + `view_scope` جدا از `approve_panels` + presetها (نسیه/تخفیف، صندوق/شیفت، انبار، سفارشی) + `panel_tier_rules` (`NORMAL` ۱۰دقیقه / `SENSITIVE_MONEY` ۵دقیقه — پیش‌فرض ناشناخته `NORMAL`).
- **دو مدل ورود:** نامحسوس `VIEW` (JWT ۱۵دقیقه + refresh) → هیچ پیامی به Electron نرود، هیچ ردیفی در AuditLog محلی ننویسد، فقط `server_audit`/`watch_log` در ابر (شفاف برای مالک، نامحسوس برای فروشنده)؛ مداخله `VIEW→ACT` با PIN دوم (۶ رقم، ۵ اشتباه→۱۵دقیقه قفل، پنجره ۱۰دقیقه بی‌کاری) → Grant + بنر + AuditLog محلی `REMOTE_GRANT`/`REMOTE_INTERVENTION` با `note` JSON + `server_audit` زنجیره‌هش‌دار (`hash_n = H(prev||row)` هر ساعت به دسکتاپ).
- **حضانت فاز۳:** فقط دیدن (از `CustodyDiscrepancyCase`/`totalTheoreticalDifference` بدون محاسبه) + هشدار؛ نوشتن حضانت روی دسکتاپ بماند (PIN شخصی `CustodyCredential:782`/`masterOverride:2594` هرگز ابری نشود). اگر تایید مدیرمحور بخواهی فقط OWNER با نشست کامل ۵دقیقه (`MANAGER`-scope) — فعلا بسته بماند.

## ۵. فاز ۴ — تلگرام/بله + Panic + نمای زنده + سلامت

- **تلگرام/بله آپشنال:** تیک خاموش پیش‌فرض در `stores.telegram_enabled` + `telegram_approve` per-member. فروشگاه هرگز به تلگرام وصل نشود، فقط ابر (`Notifier` interface → `webpush`/`telegram`/`bale`). جفت‌سازی: PWA کد ۸ نویسه ۲دقیقه‌ای → `/start` در ربات → `chat_id` به `member_id`. اگر `api.telegram.org` از ایران فیلتر بود پیام‌ها تو صف بمانند تا فیلترشکن روشن شود (بدون رله پولی) — بله بدون فیلتر پشتیبان. تایید دکمه‌ای فقط `NORMAL` ۱۰دقیقه (حساس/Panic/حضانت فقط PWA با PIN دوم) + `callback_data` امضاشده HMAC با `reqId`+`nonce` ۲دقیقه + سقف ۱۰/ساعت + اگر ۳دقیقه استفاده نشد خودکار بسته.
- **Panic:** فقط OWNER (MANAGER «درخواست Panic» می‌دهد). P1 بستن همه Grantها + `CANCELED` درخواست‌های باز + بنر قرمز؛ P2 توقف تایید از راه دور تا رمز محلی پشت دستگاه (`remote.approval.paused`). هیچ‌کدام فروش/صندوق را قفل نکند. اگر آفلاین بود Grantها با انقضای ۱۰/۵ دقیقه خودشان می‌میرند، Panic در اولین اتصال اعمال شود (state-based). خروج فقط OWNER+PIN دوم.
- **نمای زنده:** WS ابر `live:<storeId>` ≤۱ پیام/۲ث coalesce، حداکثر ۵ مشترک/فروشگاه، فاکتور در حال تایپ دیده نمی‌شود (فقط بعد ثبت). نشان تازگی سبز<۴۵ث زرد<۲دقیقه قرمز بعد. عدد آبی عینا از Snapshot.
- **هشدار:** قانون‌محور از `audit_mirror` (مغایرت/چک/سکوت سینک/شکاف هش/ری‌استور/درخواست زیاد/خارج شیفت) — تجمیع ۱ بار در ۱۰دقیقه + سقف هرزنامه + فقط به `can_view` همان پنل.
- **سلامت:** Heartbeat هر ۳۰ث `{lastAuditId, lastCaseId, epoch, chainHash, appVersion, outboxDepth, loop_lag_ms, ...}` — ابر اگر `chainHash` نخواند `pull-on-demand` همان بازه. چراغ سبز/زرد/قرمز در PWA. همه با `query_only` و backoff تا هنگ نکند.

### الحاقیه ۱ — حالت ترابری (Transport): هاب محلی + overlay، VPS اختیاری

**نتیجه بررسی کلاد۶:** Tailscale رسما در ایران «رد خدمت قانونی» (issue #9158/#9263) + پلن رایگان فقط غیرتجاری — پیش‌فرض Tailscale با فروشگاه واقعی نمی‌نشیند. راه‌حل: معماری **مستقل از ترابری** (`cloud.mode` در `cloud-state.json` کنار `panel-vault.key`).

| حالت | هاب کجاست | مسیر Electron | هزینه | توضیح |
|---|---|---|---|---|
| `HUB_LOCAL` (پیش‌فرض مجانی) | روی خود کامپیوتر مغازه (`utilityProcess` جدا ۱۲۸MB) | `ws://127.0.0.1:PORT` loopback | صفر | موبایل با هر overlay (Tailscale/Headscale/WireGuard/**Cloudflare Tunnel named**) به IP همان کامپیوتر می‌رسد — quick tunnel ثابت نیست (کلاد۷/۸)، فقط named با دامنه ثابت است |
| `OVERLAY_RELAY` | گره همیشه‌روشن روی overlay (VPS ارزان/Headscale) | WSS خروجی | کم | تقریبا طرح قبلی — `hubLocation` جدا از `mobileRoute` (کلاد۸) |
| `VPS_PUBLIC` | VPS ایران با دامنه TLS | WSS خروجی | کم | تصمیم ۳ قدیم — Cloudflare هم جزو همین خانواده (تونل به هاب) |

- **Electron تغییری نمی‌کند:** حتی در `HUB_LOCAL` هم `CloudSyncService` WS خروجی به loopback می‌زند — قانون «سرور هرگز به Electron وصل نشود» حفظ می‌شود، فقط URL عوض می‌شود. Overlay ورودی را فقط به هاب می‌رساند، نه به Electron.
- **اثر پیاده‌سازی:** `CloudSyncService` فقط `endpoints[]` به‌جای URL ثابت (+۳۰ خط) — HMAC/JSONL/epoch/heartbeat/pull بدون تغییر. `src/main/index.ts` همان ۲ خط (`:142`) — هاب داخل `startCloudSync()` با `utilityProcess` بالا می‌آید. اعتبارسنجی آدرس مثل `WooSyncService:373,691` — `ws://` فقط برای `127.0.0.1`+بازه overlay (`100.64.0.0/10`) مجاز.
- **DB هاب:** در `HUB_LOCAL` Postgres نیست — `hub.db` SQLite جدا در userData (خارج از `shop.db`) — نقشه جدول‌ها یکی است، فقط `advisory_lock` → `BEGIN IMMEDIATE`. نیاز به `better-sqlite3` (وابستگی نیتیو، نیاز به تایید).
- **امنیت:** IP overlay ≠ احراز هویت — JWT/PIN/HMAC مثل قبل. Bind فقط loopback+overlay IP، هرگز `0.0.0.0`. PWA فقط HTTPS (بدون گواهی نصب نمی‌شود).
- **آفلاین:** کامپیوتر خاموش/Sleep = «مغازه آنلاین نیست» (در `VPS_PUBLIC` تاریخچه می‌ماند). هشدار/Panic در لحظه به مدیر بدون overlay نمی‌رسد — Kill-switch دسکتاپ باقی است.
- **M1 Spike اجباری:** تست overlay روی ۳ ISP واقعی (همراه اول، ایرانسل، ADSL) + موبایل با VPN فیلترشکن روشن + HTTPS PWA + پایداری ۸ ساعته — قبل از قفل پیش‌فرض.
- **نکات کلاد دوم Tailscale:** (1) برنامه با بستن پنجره می‌بندد `index.ts:214-217` — نه Tray نه autostart — پس Tailscale همیشه روشن کافی نیست، خود برنامه هم باید باز بماند + Sleep خاموش + `powerSaveBlocker`. (2) بدون ابر هشدار قطع PC نیست — جبران: ping اختیاری «زنده‌ام» به بله هر ۵دقیقه. (3) ریشه اعتماد به PC فروشنده می‌آید — هش رمز پنل همین الان هم روی همان PC است (`Setting panel.auth`) پس بدتر نمی‌شود ولی دفاع در برابر ادمین ویندوز نیست — باید مستند شود. (4) لاگ دستکاری‌پذیر — زنجیره هش با سر زنجیره روی گوشی مالک. (5) PWA فقط HTTPS (`tailscale serve` گواهی `*.ts.net`) — `http://100.x` نصب نمی‌شود. (6) موبایل مستقیم به PC وصل می‌شود (ورودی) — `RemoteHubServer.ts` فقط `127.0.0.1` + `tailscale serve`، نه `0.0.0.0`. TTL pending ۴ دقیقه (مدیر اول Tailscale روشن کند).
- **نکات کلاد سوم Tailscale:** هاب محلی `hub.db` جدا از `shop.db` — race اولین برنده خودکار (تک‌نخی) ساده‌تر از `advisory_lock`. `better-sqlite3` + ۱ خط `electron.vite.config.ts` برای هاب لازم (نیاز به تایید ۲ مورد). تلگرام/بله در T1 خاموش (تصمیم ۲۲)، فقط T2. BackupService فقط `shop.db` را کپی می‌کند — `hub.db` باید `VACUUM INTO` روزانه جدا. Funnel هرگز روشن نشود.
