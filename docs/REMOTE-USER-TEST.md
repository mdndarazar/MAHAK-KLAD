# راهنمای تست کنترل از راه دور — فعلاً قابل اجرای کامل نیست

**وضعیت:** بخش ایجنت هنوز تمام نشده است. برنامه را برای فروشگاه نصب یا قابلیت راه دور را برای داده واقعی روشن نکنید. نه اتصال گوشی، نه تأیید مجوز، نه Panic و نه restore سرتاسری در این نسخه آماده تست پذیرش نیستند. این راهنما فعلاً فقط آزمایش‌های ایزوله کد و مراحل مورد انتظار پس از تکمیل را توضیح می‌دهد؛ برای مراحل آماده‌نشده دستور ساختگی نمی‌دهد.

## ۱. آماده‌سازی امن روی ویندوز

1. روی نسخه آزمایشیِ جداگانه و بدون اطلاعات فروشگاه کار کنید. از اطلاعات واقعی پیش از هر کار، با BackupService داخل نسخه فعلی برنامه نسخه پشتیبان بگیرید؛ بکاپ را در جای امن نگه دارید.
2. Node.js نسخه ۲۴، ۶۴ بیتی نصب باشد. پوشه سورس همین شاخه را باز کنید، در نوار آدرس پوشه `cmd` بنویسید و Enter بزنید. دستورها را در همان پنجره وارد کنید:

```cmd
node --version
node -p "process.arch"
SETUP-WINDOWS.cmd
```

نتیجه مورد انتظار: نسخه Node با `v24` شروع شود، معماری `x64` باشد و setup پیام پایان موفق بدهد. این دستورها برنامه فروشگاهی را اجرا نمی‌کنند. اگر خطا دیدید، ادامه ندهید و متن خطا را نگه دارید. setup در این محیط ویندوز **اجرا نشده است**.

## ۲. آزمایش محلیِ قطعات، بدون گوشی و داده واقعی

پس از setup، در همان پوشه دستورهای زیر را یکی‌یکی اجرا کنید:

```cmd
node --import ./test/harness/register.mjs tests/audit-fixes/remote-network-revocation.mjs
node --import ./test/harness/register.mjs tests/audit-fixes/remote-panic-identity.mjs
node --import ./test/harness/register.mjs tests/audit-fixes/remote-user-setting.mjs
node --import ./test/harness/register.mjs tests/audit-fixes/remote-cloud-disabled.mjs
```

نتیجه درست برای هر دستور: `fail 0`. این تست‌ها از فایل موقت استفاده می‌کنند و فقط قطعات آزمایشی را بررسی می‌کنند، نه کل برنامه یا تونل. روی ویندوز کاربر **اجرا نشده‌اند**.

## ۳. کلید و روشن‌کردن

کلید پیش‌فرض خاموش است. فایل تنظیمات دارای opt-in ساخته شده، اما قفل آمادگی کد جداگانه همچنان خاموش است؛ حتی نوشتن `enabled: true` چیزی را فعال نمی‌کند. **اکنون فرمان روشن‌سازی عملیاتی وجود ندارد؛ تنظیم را تغییر ندهید.** بعد از تکمیل و آزمون کد، مسیر دقیق فایل، دستور روشن و خاموش و شیوه راه‌اندازی مجدد اینجا ثبت خواهد شد.

## ۴. اتصال گوشی و تونل

**فعلاً اجرا نشود:** هاب عملیاتی و تونل واقعی آماده نشده‌اند. بعد از تکمیل، این بخش باید دستورهای دقیق مسیر تونل انتخابی، آدرس HTTPS معتبر و روش بازکردن آن در گوشی را ارائه کند. نتیجه درست باید بازشدن صفحه از گوشی بدون هشدار گواهی و رد دسترسی‌های غیرمجاز باشد. از بازکردن مستقیم پورت برنامه در اینترنت خودداری کنید.

## ۵. درخواست و تأیید مجوز

**فعلاً اجرا نشود:** اتصال کامل مجوز به هاب و دسکتاپ آماده نیست. پس از آماده‌شدن، فروشنده باید از دسکتاپ درخواست دهد؛ مالک پس از مطابقت کد شش‌رقمی روی هر دو صفحه و ورود PIN تأیید کند. نتیجه درست بازشدن فقط پنل و پنجره مجاز برای مدت مقرر است؛ بدون تأیید یا با کد نادرست هیچ مجوزی نباید باز شود.

## ۶. Panic

**فعلاً اجرا نشود:** Panic سرتاسری به برنامه متصل نیست. پس از آماده‌شدن، مالک باید Panic را با PIN اجرا کند؛ نتیجه درست بسته‌شدن همه مجوزها و درخواست‌ها، پایان نشست‌ها و اطلاع دسکتاپ است. راه بازگشت امن و دستورهای دقیق پس از پیاده‌سازی ثبت می‌شوند. Panic نباید فروش عادی را قفل کند.

## ۷. restore آزمایشی

**فعلاً اجرا نشود:** تشخیص و هماهنگی restore واقعی تکمیل نشده است. پس از آماده‌شدن، فقط در نصب آزمایشی و روی دیتابیس موقت بکاپ ساخته و restore می‌شود؛ نتیجه درست ابطال درخواست‌ها و مجوزهای قبلی، ساخت epoch جدید و همگام‌سازی مجدد است. در صورت خطا، راه دور باید بسته بماند. هیچ آزمون restore را روی داده واقعی انجام ندهید.
