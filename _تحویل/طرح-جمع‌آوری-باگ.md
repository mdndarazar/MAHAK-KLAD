**نتیجهٔ راستی‌آزمایی (batch-014):** ادعا **نادرست** بود و علتش خودِ تست من بود:
مقدار درست `restrictScope` برابر **`VARIANTS`** (جمع) است و من `VARIANT` (مفرد) فرستاده بودم.
با مقدار درست، هر ۹ سناریو کاملاً درست کار کرد:

| سناریو | مصرف شد؟ | درست |
|---|---|---|
| اعتبار تک‌کالا (کالای ۱) ⇒ کالای ۲ | نه (`ACTIVE`) | ✅ |
| اعتبار تک‌کالا (کالای ۱) ⇒ کالای ۱ | بله | ✅ |
| اعتبار دوکالا (۱+۲) ⇒ کالای ۲ | بله | ✅ |
| اعتبار دوکالا (۱+۲) ⇒ کالای ۳ | نه | ✅ |
| اعتبار تک‌دسته ⇒ دستهٔ دیگر / همان دسته | نه / بله | ✅ |
| اعتبار چنددسته ⇒ دستهٔ مجاز / غیرمجاز | بله / نه | ✅ |
| `ALL` ⇒ هر کالا | بله | ✅ |

### B-2 — 🐞 باگ عادی (تأییدشده توسط مالک) · **ضرورت پایین**

**عنوان:** مقدار نامعتبرِ محدوده، بی‌صدا به «همهٔ کالاها» تبدیل می‌شود (fail-open)

- **فایل:** `src/shared/credit.ts:529` — `normalizeRestrictScope`
```ts
export function normalizeRestrictScope(raw: unknown): CreditRestrictScope {
  const v = String(raw ?? '').trim().toUpperCase()
  return v === CreditRestrictScope.CATEGORY || v === CreditRestrictScope.VARIANTS
    ? (v as CreditRestrictScope)
    : CreditRestrictScope.ALL          // ← هر مقدار ناشناخته = ALL
}
```
- **مشاهدهٔ تجربی:** با `restrictScope: 'VARIANT'` (مفرد) اعتبار به‌جای رد شدن، **بدون محدودیت** صادر و روی کالای دیگر خرج شد.
- **ریسک واقعی:** هر اشتباه تایپی یا payload ناقص از IPC ⇒ بارکد **بدون محدودیت** صادر می‌شود (باز شدن به‌جای بستن).
- **انتظار پیشنهادی:** مقدار ناشناخته ⇒ خطا («محدودهٔ اعتبار نامعتبر است»)، نه ALL.
- **اثر پولی:** بالقوه — اعتبار محدود به یک کالا، عملاً نامحدود می‌شود.
- **تأیید مالک:** ✅ تأیید شد (با تصریح: «ضروری نیست، فقط بمانَد که بعداً یادمان باشد»)
