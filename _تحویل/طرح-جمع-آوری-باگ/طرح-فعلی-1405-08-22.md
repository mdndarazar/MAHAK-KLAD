### مورد ۲ — چک PENDING سقف رزرو نمی‌کند + جایگزینی با نقد (کم‌اهمیت) ✅ تایید شد ۱۴۰۵/۰۸/۲۲
- **ریشه:** `src/main/services/SalesService.ts:12793-12800` — `addPayment` نقد، `pendingChequeTotal` را در `remainingBefore` لحاظ نمی‌کند → نقد ۴۰۰k روی فاکتور ۴۰۰k با چک ۱۰۰k PENDING قبول می‌شود → پس از پاس ۵۰۰k می‌شود.
- **اهمیت:** کم (به درخواست تو — حتی با اینکه اثر ۱۰۰k دارد، چون راه دستیِ ابطال وجود دارد)
- **سیاست مالک (که تو الان دقیق کردی):**
  1. فروشنده باید با اسکن **بارکد فاکتور** در بخش چک‌ها، چک‌های مربوط به همان فاکتور را فوری پیدا کند.
  2. همین اسکن برای **نسیه** هم باید کار کند — با اسکن بارکد فاکتور، بخش پرداخت‌های نسیهٔ همان فاکتور باز شود.
  3. روی هر چکِ PENDING یک گزینه باشد: **«جایگزینی با نقد»** (یا «جایگزینی با نقد/کارت»)
  4. فروشنده گزینه را می‌زند → سیستم مبلغ را می‌پرسد → فروشنده وارد می‌کند:
     - اگر مبلغ == مبلغ چک → اوکی → چک همان‌جا باطل (void) شود و نقد/کارت ثبت شود **در یک تراکنش اتمیک**
     - اگر مبلغ < مبلغ چک → اخطار: «حتما باید قبلش چک جدید برای باقی‌مانده ثبت کنید» — مثلاً چک ۱۰۰k، نقد ۶۰k → باید اول چک ۴۰k جدید ثبت شود، بعد این عملیات
     - اگر مبلغ > مبلغ چک (یا > سقف درست `remaining - pendingOther`) → ثبت نکند و بگوید «مبلغ بیشتر از حد مجاز»
  5. پول نقد/کارتی که همان روز گرفته شد باید به **عدد مرجع آبی** (عدد مرجع روزانهٔ گزارش/صندوق) اضافه شود — یعنی در `CashMovement` و گزارش شیفت همان روز بیاید.
- **مثال مبتدیانهٔ همین مورد:**
  - فاکتور ۴۰۰k نسیه، چک ۱۰۰k PENDING
  - فردا مشتری می‌آید: «۴۰۰k نقد می‌دهم، چک‌ام رو بده»
  - فروشنده بارکد فاکتور را اسکن می‌کند → لیست چک‌های همان فاکتور (۱۰۰k) می‌آید
  - روی چک می‌زند «جایگزینی با نقد» → سیستم می‌پرسد «چقدر نقد گرفتی؟» → فروشنده ۴۰۰k می‌زند
  - سیستم می‌بیند مبلغ چک (۱۰۰k) ≠ ۴۰۰k → ولی منطق درست: چک ۱۰۰k باید باطل شود و ۴۰۰k نقد ثبت شود — جمع نهایی ۴۰۰k نقدِ خالص، بدون چک. اگر سیاست‌ات «چک باید دقیقاً با نقد جایگزین شود» است، باید ۱۰۰k نقد بگیرد و برای ۳۰۰k باقی‌مانده یا چک جدید ۳۰۰k بگیرد یا بگوید ۳۰۰k نقدِ اضافه برای بدهیِ بدون چک است. (تو گفتی اگر کمتر بود بگو چک جدید بیار؛ اگر برابر بود اوکی)
  - پس از تایید: `deletePayment(چک 100k) + addPayment(400k نقد)` اتمیک → `paidTotal 400k` درست
- **سناریوی تست طرح برای این مورد:**
  1. نسیه ۴۰۰k → چک ۱۰۰k → اسکن بارکد فاکتور → چک پیدا شود
  2. «جایگزینی با نقد» → مبلغ ۴۰۰k → اگر `amount > remaining - pendingOther + chequeAmount`؟ سیستم باید اتمیک انجام دهد و چک باطل شود
  3. چک ۱۰۰k → نقد ۶۰k (کمتر) → باید اخطار «چک جدید ۴۰k ثبت کن» دهد و ثبت نکند
  4. چک ۱۰۰k → نقد ۱۰۰k (برابر) → اوکی، چک باطل + نقد ثبت، عدد آبی +۱۰۰k
  5. چک ۱۰۰k → نقد ۱۲۰k (بیشتر از چک+سقف) → رد
