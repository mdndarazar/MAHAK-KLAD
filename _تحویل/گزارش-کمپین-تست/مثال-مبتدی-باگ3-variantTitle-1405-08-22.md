# مثال مبتدیانه — باگ ۳: `variantTitle is not defined` (برداشت خودکار از مرکزی)

> نشانی: `src/main/services/SecondaryStockService.ts:1190`
> `variantTitle` در `src/shared/stockSource.ts:521` تعریف شده ولی در `SecondaryStockService` import نشده

---

## ۱) این ویژگی چیه؟ (خیلی ساده)

تو دو تا انبار داری:
- **انبار فروشگاه** (همون قفسهٔ جلوی مشتری) — موجودی‌اش تو `ProductVariant.stock` است
- **انبار مرکزی** (انبار پشت یا انبار اصلی شهر) — موجودی‌اش تو `SecondaryStockItem` است

یه تیک داری: **«برداشت خودکار از انبار مرکزی هنگام کمبود»** (`autoCentralWithdraw`)

- تیک **خاموش** (پیش‌فرض): اگر فروشگاه ۱ دونه دارد و مشتری ۳ تا می‌خواهد → فروش ثبت می‌شود، موجودی فروشگاه می‌شود **منفی ۲**، فقط یه هشدار زرد می‌آید: «موجودی منفی شد». انبار مرکزی دست نمی‌خورد.

- تیک **روشن**: اگر فروشگاه ۱ دارد و ۳ می‌خواهد → اول سیستم می‌رود انبار مرکزی، ۲ تا از اونجا برمی‌دارد می‌آورد به فروشگاه، بعد می‌فروشد → فروشگاه ۰ می‌ماند، مرکزی کم می‌شود، هشدار «۲ تا از مرکزی آمد» می‌آید.

این تیک برای همین ساخته شده که کمبود فروشگاه خودکار جبران شود.

## ۲) مثال با عدد

**قبل فروش:**
- کالا: نوشابه ۱٫۵ لیتری — واریانت `sz1`
- انبار فروشگاه: **۱ عدد**
- انبار مرکزی: **۵ عدد** (ردیف `SecondaryStockItem` با `code: sz1`, `qty:5`)

**مشتری:** ۳ تا نوشابه می‌خواهد
**کمبود:** ۲ تا (۳ - ۱ = ۲)

**انتظار درست (تیک روشن):**
```
1. از مرکزی 2 تا بردار → مرکزی 5→3، فروشگاه 1→3
2. از فروشگاه 3 تا کم کن → فروشگاه 3→0
3. فاکتور ثبت شود — 3× قیمت
4. پیام: «۲ عدد از انبار مرکزی (مرکزی) برداشته شد»
```

**رفتار فعلی (باگ):**
```
1. فروش ثبت می‌شود → می‌رود سراغ coverShortage
2. در حلقهٔ shortages:
   const title = variantTitle(v)  // ← اینجا می‌ترکد!
   ReferenceError: variantTitle is not defined
3. کل تراکنش rollback — هیچ فاکتوری ثبت نمی‌شود، هیچ موجودی کم نمی‌شود
```

یعنی **دقیقاً وقتی به این ویژگی نیاز داری (کمبود هست)**، فروش کلاً می‌پاشد.

## ۳) چرا شد؟ یک خط import جا افتاده

در `src/shared/stockSource.ts:521`:
```ts
export function variantTitle(v){...}
```

در `src/main/services/SecondaryStockService.ts` بالای فایل importها:
```ts
import { prisma } from '../db/client'
import { inventoryService } from './InventoryService'
// ... هیچ import از stockSource نیست
```

ولی در خط ۱۱۹۰:
```ts
const title = variantTitle(v) // ← استفاده بدون import
```

تایپ‌اسکریپت در حالت عادی خطا می‌دهد ولی چون `isolatedModules` و تست‌ها این مسیر را کم اجرا کرده بودند، تا الان پنهان مانده.

نکته: فایل یک خط دارد:
```ts
export { MATCH_REASON_LABELS, matchRank, variantTitle } from '@shared/stockSource'
```
این **re-export** است نه **import** — یعنی «من هم صادر می‌کنم» ولی «من ندارمش برای استفادهٔ داخلی».

## ۴) اثرش چیه؟

- **مسیر بدون کمبود:** کار می‌کند (چون `coverShortage` اصلاً صدا زده نمی‌شود)
- **مسیر با کمبود و تیک خاموش:** کار می‌کند (چون مرکزی دست نمی‌خورد)
- **مسیر با کمبود و تیک روشن:** **همیشه می‌پاشد** — ۱۰۰٪ — چون دقیقاً همین کد اجرا می‌شود

یعنی کل ویژگیِ «جبران خودکار کمبود» که برایش تیک گذاشتی، **هیچ‌وقت کار نکرده** وقتی واقعاً کمبود بوده.

## ۵) مثال دوم — چند قلم

- قلم A: فروشگاه ۰، مرکزی ۱۰ — درخواست ۲ → کمبود ۲
- قلم B: فروشگاه ۵، مرکزی ۰ — درخواست ۳ → کمبود ۰ (کافی است)
- با تیک روشن: باید A از مرکزی ۲ بیاید، B مستقیم از فروشگاه → الان روی A می‌ترکد و کل فاکتور (حتی B) هم ثبت نمی‌شود.

## ۷) درستش چیست؟ (بدون اعمال — فقط برای فهم)

```ts

```

**جمع:** باگِ «ویژگیِ همیشه‌خراب» — نه پول گم می‌شود نه اضافه می‌گیرد، ولی فروش در دقیقاً همان حالتِ موردنیاز ثبت نمی‌شود.
**وضعیت طرح:** ⏳ هنوز در انتظار تایید تو — اگر تایید کنی وارد طرح می‌شود (اهمیت: متوسط — چون فروش در کمبود قفل می‌شود، ولی پول جابه‌جا نمی‌شود).
