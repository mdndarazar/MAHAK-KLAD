# مثال مبتدیانه — باگ ۱: چک PENDING سقف را رزرو نمی‌کند

> این مثال دقیقاً همان چیزی است که در هارنس بازتولید شد. هیچ اصطلاح فنی اضافه‌ای نیست؛ فقط پول و رسید.

---

## ۱) داستان خرید

**مشتری:** حسین کریمی — ۰۹۱۲۱۲۳۴۵۶۷۸۹  
**فروشنده:** تو — شیفت شب — تاریخ ۱۴۰۵/۰۸/۲۲  
**کالا:** یک یخچال ۴۰۰٬۰۰۰ ریال (برای ساده‌بودن، یک قلم)

تو فاکتور را **نسیه** ثبت می‌کنی — یعنی هنوز هیچ پولی از مشتری نگرفته‌ای.

```
فاکتور #1
  جمع کل (grandTotal) = 400,000 ریال
  پرداخت شده (paidTotal) = 0
  مانده بدهی (remaining) = 400,000
  وضعیت = پرداخت‌نشده (UNPAID)
```

## ۲) مشتری یک چک می‌دهد

مشتری می‌گوید: «۱۰۰٬۰۰۰ ریال را با چک می‌دهم، بقیه را فردا نقد می‌آورم.»

تو چک را ثبت می‌کنی:
- مبلغ: ۱۰۰٬۰۰۰
- شماره: ۱۲۳۴۵۶
- بانک: ملی
- سررسید: ۱۴۰۵/۱۲/۱۰
- وضعیت: **PENDING (در جریان)** — هنوز پاس نشده، هنوز پول نیست

طبق قانون برنامه: «چک تا پاس نشدن، پولِ دریافت‌شده نیست.» پس:
```
paidTotal هنوز 0 (درست)
remaining هنوز 400,000 (درست — چون پول نشده)
pendingChequeTotal = 100,000 (الان این چک توی کشو خوابیده)
```

**تا اینجا همه درست است.**

## ۳) اشتباهِ سیستم — سقف رزرو نمی‌شود

فردا مشتری می‌آید و می‌گوید: «۴۰۰٬۰۰۰ را نقد می‌دهم، بدهی‌ام صفر شود.»

**انتظار درست چیست؟**
تو باید بگویی: «نه، تو ۱۰۰٬۰۰۰ چک در جریان داری. اگر ۴۰۰٬۰۰۰ نقد بگیری، وقتی چک پاس شود جمع دریافتی‌ات ۵۰۰٬۰۰۰ می‌شود — یعنی ۱۰۰٬۰۰۰ اضافه از مشتری گرفته‌ای. اضافه‌پرداخت در هیچ حالتی مجاز نیست. حداکثر ۳۰۰٬۰۰۰ نقد می‌توانی بگیری.»

یعنی:
```
سقفِ درستِ نقد = remaining - pendingCheque = 400,000 - 100,000 = 300,000
درخواست 400,000 → باید REJECT شود با پیام:
«مبلغ واردشده 400,000 از باقی‌ماندهٔ 400,000، 100,000 بیشتر است...»
```

**رفتار فعلی (باگ):**
سیستم فقط به `remaining = 400,000` نگاه می‌کند و چون `400,000 <= 400,000` است، **قبول می‌کند**:
```
✅ نقد 400,000 ثبت شد
paidTotal = 400,000
remaining = 0
pendingChequeTotal = 100,000 (هنوز جدا)
→ فاکتور «تسویه شد» نشان داده می‌شود — در حالی که 100k هنوز در هواست!
```

## ۴) چک پاس می‌شود — فاجعهٔ ۱۰۰٬۰۰۰ اضافی

مدیر چک را پاس می‌کند:
```
setChequeStatus(id, status='CLEARED', destination='MANAGER', password='1111')
```

حالا چک هم «پولِ دریافت‌شده» حساب می‌شود:
```
paidTotal = 400,000 (نقد) + 100,000 (چکِ پاس‌شده) = 500,000
grandTotal = 400,000
overpayTotal = 100,000  ← پول واقعیِ اضافه در کشو/حساب مدیر نشسته
remaining = 0
```

**نتیجه:**
- فاکتور ۴۰۰هزاری، ۵۰۰هزار پول گرفته.
- گزارش «اضافه‌دریافت» ۱۰۰k را جدا نشان می‌دهد ولی پول واقعاً گرفته شده.
- سیاست مالک می‌گوید: «اضافه‌پرداخت در هیچ حالتی مجاز نیست؛ رمز مدیر هم آن را مجاز نمی‌کند.» — ولی اینجا با رمز مدیرِ پاسِ چک، دور زده شد.

## ۵) چرا شد؟ یک خط کد

در `SalesService.ts:12796-12800` وقتی `addPayment` نقدی صدا می‌زنی:
```ts
remainingBefore = invoiceRemaining(grandTotal, receivedTotalOf(priorRows))
// receivedTotalOf = فقط CLEARED ها → چک PENDING شمرده نمی‌شود → 400,000
overpayAmount = amount - remainingBefore // 400,000 - 400,000 = 0 → رد نمی‌شود
```

چک PENDING عمداً در `remainingBefore` نیست، ولی هیچ‌جا هم به‌عنوان «رزرو سقف» کم نمی‌شود.

## ۶) درستش چه بود؟ (بدون اعمال — فقط برای فهم)

قبل از تأیید نقد، باید:
```
reserved = pendingChequeTotalOf(priorRows) // 100,000
effectiveRemaining = max(0, remainingBefore - reserved) // 300,000
اگر amount > effectiveRemaining → REJECT
```

یا به‌زبان ساده: «هر چی چک در جریان داری، از سقفی که می‌توانی نقد بگیری کم کن.»

## ۷) مثال عددیِ دوم (کوچک‌تر)

- فاکتور ۱٬۰۰۰٬۰۰۰
- چک ۳۰۰٬۰۰۰ PENDING → سقف نقد باید ۷۰۰٬۰۰۰ باشد
- نقد ۷۰۰٬۰۰۰ → درست، قبول
- نقد ۷۰۰٬۰۰۱ → باید REJECT (۱ ریال اضافه) — فعلاً قبول می‌شود و بعد از پاس، ۱ ریال اضافه می‌سازد.

## ۸) مدرک هارنس (خلاصه)

```
created invoice 1 grandTotal 400000 paidTotal 0
after pending cheque 100k pendingChequeTotal 100000 remaining 400000
cash 400k ACCEPTED (BUG!) paidTotal 400000
after cheque CLEARED paidTotal 500000 grandTotal 400000 overpay 100000
BUG CONFIRMED
```

همین سناریو در `f7_cheque_debt.js` با ۲۵ ترکیب (۳ مبلغ چک × ۳ حالت نقد × ۳ نوع پرداخت اولیه) به‌صورت خودکار fail شد: `OVER-COMMIT: counted 400000 + pending 100000 = 500000 > 400000`.

---
**جمع:** این باگ پول را گم نمی‌کند — بلکه **اضافه می‌گیرد**. خطرش این است که صندوق/حساب مدیر بی‌صدا پر می‌شود و در بستن صندوق «اضافه» پنهان می‌ماند.
