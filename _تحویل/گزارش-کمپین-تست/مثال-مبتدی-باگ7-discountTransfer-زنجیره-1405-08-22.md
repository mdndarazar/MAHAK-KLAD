# مثال مبتدیانه — مورد ۷: ستون `discountTransferOption` در زنجیرهٔ تعویض

> نشانی: `src/main/services/SalesService.ts:9579` — `historicalDiscount > 0 ? selectedOption : null`
> روی تعویضِ روی تعویض، `historicalDiscount` صفر برمی‌گردد → ستون `null` می‌شود، ولی مبلغ‌ها درست است

---

## ۱) انتقال تخفیف یعنی چی؟ (خیلی ساده)

تو یه جنس رو با تخفیف فروختی، بعد مشتری می‌خواهد عوض کند. سه انتخاب داری:

- **NO:** تخفیف قبلی را نده به جنس جدید — جنس جدید با قیمت کامل
- **YES:** تخفیف قبلی را کامل ببر روی جنس جدید — مثلاً ۵۰۰k تخفیف داشتی، ۵۰۰k بده به جنس جدید
- **YES_ZERO:** اگر اختلاف مثبت بود (جنس جدید گران‌تر)، تا سقف اختلاف تخفیف بده، وگرنه صفر

این انتخاب تو ستون `discountTransferOption` ذخیره می‌شود برای حسابرسی.

## ۲) مثال با عدد — تعویض اول (درست)

**فاکتور اول:**
- کاپشن ۲٬۰۰۰٬۰۰۰ — تخفیف ردیفی ۵۰۰٬۰۰۰ → پرداختی ۱٬۵۰۰٬۰۰۰
- `historicalDiscount = 500,000`

**تعویض اول — انتخاب YES:**
- کاپشن را پس می‌دهد (۱٬۵۰۰٬۰۰۰ ارزش با تخفیف)
- کفش ۲٬۰۰۰٬۰۰۰ برمی‌دارد — تخفیف ۵۰۰٬۰۰۰ منتقل می‌شود → کفش ۱٬۵۰۰٬۰۰۰
- فاکتور تعویض: `discountTransferOption = 'YES'` ✅ — درست ثبت شد
- جنس جدید (کفش) خودش ۵۰۰٬۰۰۰ تخفیفِ منتقل‌شده دارد

## ۳) تعویض دوم — روی سند تعویض (باگِ ستون)

حالا مشتری فردا می‌آید می‌گوید «کفش را هم عوض می‌کنم» — یعنی **تعویضِ روی تعویض** (زنجیره):

- کفشِ ۱٬۵۰۰٬۰۰۰ (که ۵۰۰k تخفیفِ منتقل‌شده دارد) را پس می‌دهد
- کت ۲٬۰۰۰٬۰۰۰ برمی‌دارد — این بار انتخاب **NO** (نمی‌خواهد تخفیف منتقل شود)

**انتظار درست:**
```
فاکتور تعویض دوم: discountTransferOption = 'NO' ✅
historicalDiscount (برای حسابرسی) = 500,000 (همانی که واقعاً روی کفش بود)
مبلغ‌ها: NO → کت ۲٬۰۰۰٬۰۰۰ بدون تخفیف → اختلاف +۵۰۰k → مشتری ۵۰۰k می‌دهد → درست
```

**رفتار فعلی:**
```
مبلغ‌ها: درست — ۲٬۰۰۰٬۰۰۰ بدون تخفیف → ۵۰۰k دریافتی ✅ (پول درست)
ولی ستون: discountTransferOption = null ❌ (به‌جای 'NO')
و historicalDiscount که خوانده می‌شود = 0 (به‌جای 500,000)
```

یعنی **پول و حساب درست است، فقط کاغذِ حسابرسی ناقص است** — نمی‌فهمی این تعویض با کدام گزینه بوده.

## ۴) چرا شد؟ یک شرطِ اشتباه

در `9579`:
```ts
discountTransferOption: historicalDiscount > 0 ? selectedTransferOption : null
```

برای زنجیره، `historicalDiscount` از تابعِ `getHistoricalDiscountForExchange` می‌آید که برای سندِ تعویضی (زنجیره) صفر برمی‌گرداند — چون فکر می‌کند «این سند خودش تخفیف ندارد» — در حالی که **دارد** (۵۰۰k منتقل‌شده).

پس چون `0 > 0` غلط است → `null` می‌نویسد.

## ۵) اثرش چیه؟

- **پول:** صفر اختلاف — همهٔ ۳۶ ترکیبِ `NO/YES/YES_ZERO × Δ` درست حساب می‌شود
- **ستون:** `null` به‌جای `'NO'` — در گزارش «سهم تخفیف تاریخی» نمی‌فهمی این سند با کدام گزینه بوده
- **حسابرسی:** اگر بخواهی بعداً بفهمی «چرا این تعویض زنجیره‌ای NO بوده؟» جوابی نیست

## ۶) مثال ساده‌تر

- فاکتور ۱۰۰k — تخفیف ۲۰k → ۸۰k
- تعویض YES → جنس جدید ۱۰۰k با ۲۰k تخفیف → ۸۰k
- تعویض دوم NO → جنس سوم ۱۲۰k بدون تخفیف → باید ۴۰k بدهی → درست ۴۰k، ولی ستون null

---
**جمع:** باگِ «دفترِ ناقص» — پول درست، فقط یه ستون خالی می‌ماند.
**وضعیت طرح:** ⏳ هنوز در انتظار تایید تو — اگر بگویی «ثبت گزینه برای حسابرسی مهم است» وارد طرح می‌شود (اهمیت: کم)، وگرنه همین ذخیره می‌ماند.
