# Audit sections §10–§17 — مدیریت اعتبار خرید

## §10 — PARTIAL
- evidence: `prisma/schema.prisma:1067-1082` — `AuditLog` stores `at`, `userId`, `action`, `entity/entityId`, JSON `before/after`, and `note`.
- evidence: `src/main/services/StoreCreditService.ts:681-705` — issue writes a StoreCredit audit event; `:1077-1106` — redemption writes exact applied amount, before/after used values, invoice/payment IDs, user and time-backed audit row.
- evidence: `src/main/services/StoreCreditService.ts:1211-1245` — manager changes require manager password and reason, validate transitions, and audit before/after/reason; `:1248-1598` covers void, reactivate, expiry, amount, uses, holder, restriction, delete/archive.
- evidence: `src/main/services/StoreCreditService.ts:2123-2172` — detail loads StoreCredit AuditLog rows into the Timeline; `src/renderer/src/pages/CreditManagement.tsx:31-33,164,218` — the timeline is behind the credit-management gate and is rendered.
- evidence: `src/main/services/AuditService.ts:69-84` — audit write errors are caught and only logged, so a business change can succeed without a persisted audit event.
- evidence: `src/main/services/StoreCreditService.ts:1475-1485` — holder-change `before` records only customer/name/lock/company/phone, while national ID, address, representative, note and opt-out are omitted from the before snapshot.
- evidence: `src/main/services/MaintenanceService.ts:251-253`; `src/main/ipc/index.ts:314-317` — old AuditLog rows can be physically deleted through the maintenance IPC path without a service-side manager-password assertion or credit/audit-specific retention guard.
- gap: BACKEND — make audit persistence fail closed/transactional for credit mutations, snapshot every changed holder field in `before`, and protect or explicitly exclude StoreCredit audit rows from the unprotected maintenance purge; an ordinary IPC caller must not be able to erase history.
- gap: UI(renderer) — the renderer has a gated Timeline, but no separate immutable audit-log view/retention control; the second-password protection is only the credit-management page gate, not a backend protection for the audit-log purge path.

## §11 — PARTIAL
- evidence: `src/shared/credit.ts:264-325` — defines DRAFT/ACTIVE/PARTIALLY_USED/USED/EXPIRED/CANCELED/SUSPENDED, redeemable states, and an explicit transition table with `canCreditTransition`.
- evidence: `src/main/services/StoreCreditService.ts:954-978` — redemption computes the next state, validates the transition, and atomically updates only expected status/used values; `:1211-1245` applies the same validation to manager operations.
- evidence: `src/main/services/StoreCreditService.ts:1248-1266` — void is a CANCELED status update; `:1550-1598` — unused credits are physically deleted, while credits with redemptions/payments/usage are archived with `deletedAt`.
- evidence: `src/renderer/src/pages/CreditManagement.tsx:193,209-213,218` — all status-changing/deletion operations are exposed through operation buttons and the operation form asks for manager password and reason; there is no free-form status setter.
- evidence: `src/main/services/StoreCreditService.ts:1137-1165` — the exported invoice-reversal helper directly writes `status` without `canCreditTransition`; its own comment says SalesService still does not call it.
- evidence: `src/shared/credit.ts:399-403`; `src/main/services/StoreCreditService.ts:2234-2281` — expiry is often only an effective/display status while dashboard grouping uses raw `status`, so an expired ACTIVE row can remain stored ACTIVE and be counted as active.
- gap: BACKEND — route every status write, including invoice-redemption reversal, through the transition validator and persist/reconcile EXPIRED state consistently; do not leave expired ACTIVE records in raw status when status-machine/report consumers read the column.

- evidence: `src/renderer/src/pages/Pos.tsx:594-626,1437-1450` — selected cash/card payment is sent as the residual amount while `storeCreditCode`, optional requested amount, and idempotency key are sent on the same sale; UI displays the split.
