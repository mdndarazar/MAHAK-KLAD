# دستهٔ ۲۸ — شکارِ باگِ منطقیِ ۱۰٬۰۰۰تایی (هر ۱۰k توقف و گزارش)

**شعار:** «باگِ الکی نساز — اگه هست بگو، اگه نیست هم صادقانه بگو.»

> طبقِ خواسته‌ت: **هر ۱۰٬۰۰۰ تست متوقف شو و گزارش بده.** این سومین ۱۰٬۰۰۰تایِ این سریه — این بار با حالتِ **شکارِ باگ** (hunt): هر سناریو علاوه بر «پاس/رد»، **invariantهای ریالی** رو هم از روی جدول‌های خام چک می‌کنه و اگه کوچک‌ترین باگِ منطقی پیدا بشه، همون‌جا متوقف میشه و باگ رو گزارش میده.

دادهٔ خام: `batch-034-10000-hunt.jsonl` — ۱۰٬۰۰۰ ردیف

## نتیجهٔ شکارِ این ۱۰k

- سناریوهای اجراشده: **۱۰٬۰۰۰**
- پاس: **۷٬۰۰۰**
- ردِ منطقی (درست): **۳٬۰۰۰**
- شکستِ واقعی: **۰**
- باگِ منطقیِ شکارشده: **۰**

```text
۱۰۰۰۰ سناریو، ۷۰۰۰ پاس، ۳۰۰۰ ردِ منطقی، ۰ باگ
```

### باگ پیدا شد؟

**نه — در این ۱۰٬۰۰۰تا باگِ منطقیِ واقعی پیدا نشد.** و چون گفتی «باگِ الکی نساز»، همین رو صادقانه گزارش می‌دم، نه یه باگِ ساختگی.

> اگه باگ بود، همین‌جا متوقف می‌شد و با `result: BUG` و `invariants`ِ کامل ثبت می‌شد. در این کمپین چنین ردیفی ثبت نشد.

## این ۱۰٬۰۰۰تا چی رو شکار می‌کرد؟

هر سناریو ۱۰ قالبِ شکار، هر کدام ۱۰۰۰ بار:

| قالبِ شکار | invariantای که چک شد |
|---|---|
| **hunt-discount-transfer** | انتقالِ تخفیفِ تاریخی نباید برگشتی رو بزرگ‌تر کنه |
| **hunt-credit-category** | اعتبارِ دستهٔ A نباید روی کالایِ دستهٔ B برگرده (`returnCreditAmount` باید ۰ باشه) |
| **hunt-exchange-debt-cheque** | تعویضِ منفی روی فاکتورِ چک‌دار: چک باید `flagged` بمونه نه `void` وقتی B هنوز >۰ |
| **hunt-stock-no-deduct** | `deductInventory:false` → موجودی نباید تکان بخوره |
| **hunt-credit-partial-carry** | `carryRemainder=false` → `usedAmount` باید دقیقاً ۵۰k بمونه |
| **hunt-overpay-second-payment** | دومین پرداخت که جمع رو از `grand` رد کنه → باید با اختلافِ دقیق رد بشه |
| **hunt-refund-none-auto** | بازپرداختِ نقدیِ ۲۰۰k روی برگشتِ کاملِ ۲۰۰k → باید ۲۰۰k برگرده |
| **hunt-cheque-cleared-return** | چکِ پاس‌شده → برگشت → `remaining` باید درست صفر/غیرصفر بشه |
| **hunt-wholesale-discount** | ۱۰۰ قلمیِ ۱۰٪ عمده → `grandTotal` باید ۴٫۵M باشه |
| **hunt-duplicate-exchange** | تعویضِ دوبارهٔ همون قلم → «قبلاً تعویض شده» |

روی هر سناریو بعد از `PASS`، این چک‌ها از روی `Payment`, `SaleReturn`, `CreditReturnAllocation`, `ProductVariant.stock` انجام شد.
